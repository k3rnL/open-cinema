# V1 software acceptance record — 2026-08-22

Decision: the orchestration software boundary is accepted for continued
coordinated release work. It is **not** accepted as the default Raspberry Pi
runtime until physical hardware measurements and the release pin/checkpoint are
complete.

Accepted evidence:

- backend model, schema, resolver, reconciliation, processor, API, security,
  deployment-contract, and canonical acceptance suites;
- WyrePlumber runtime contract/native binding suites against WirePlumber 0.5;
- decoder status protocol and fixture suites;
- shared UI contract, simple/admin UI, and browser acceptance suites;
- isolated D-Bus/PipeWire/WirePlumber development container with deterministic
  TV, speakers, and headset nodes;
- Ansible syntax, preflight, lifecycle, readiness, destructive-schema backup,
  and bounded rollback policies.

Open blockers at this checkpoint:

- immutable coordinated component releases and production pins;
- HDMI/USB/S/PDIF and Bluetooth role verification on each target Pi tier;
- latency, audible gap, CPU, memory, SQLite, throughput, and retention
  measurements used to set final appliance bounds;
- successful staged rollout and hardware checkpoint before default enablement.

The complete requirement mapping and current evidence paths are in
[the acceptance report](../ACCEPTANCE_REPORT.md). Follow-up work that is outside
the first accepted release has dedicated OpenSpec changes for native decoder
PipeWire I/O, additional managed-link shapes, and multi-instance scaling.
